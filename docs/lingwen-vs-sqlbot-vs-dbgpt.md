## 二、核心能力对比

### 2.1 Text2SQL / 查询管线

| 能力 | Lingwen | SQLBot | DB-GPT |
|------|---------|--------|--------|
| **管线节点数** | 8 步 | ~4-5 步 | 可编排 DAG |
| **意图识别** | ✅ LLM 意图分类 | ✅ | ✅ 多 Agent 路由 |
| **RAG Schema 检索** | ✅ ChromaDB (top-k=5) | ✅ | ✅ 多索引（向量+倒排+图） |
| **RAG Few-shot 检索** | ✅ ChromaDB (top-k=3) | ✅ | ✅ |
| **CoT 推理生成** | ✅ DeepSeek | ✅ | ✅ 多模型支持 |
| **SQL 安全校验** | ✅ SqlGuard（刚修复） | ✅ | ✅ |
| **LIMIT 注入** | ✅ 1000 行 | ✅ | ✅ |
| **自动重试** | ✅ 最多 2 次 | ❓ | ✅ |
| **方言提示注入** | ✅ 8 种方言 | ❓ | ✅ 多数据库 |
| **元数据回退** | ✅ RAG 空时 DB 查询 | ❓ | ✅ |

**评估**: Lingwen 的 8 步管线设计最为精细，方言注入和元数据回退是差异化优势。DB-GPT 的可编排 DAG 更灵活但有学习成本。

### 2.2 多数据源支持

| 数据源 | Lingwen | SQLBot | DB-GPT |
|--------|---------|--------|--------|
| MySQL | ✅ | ✅ | ✅ |
| PostgreSQL | ✅ | ✅ | ✅ |
| ClickHouse | ✅ | ❓ | ✅ (experimental) |
| Oracle | ✅ | ❓ | ✅ (experimental) |
| Apache Doris | ✅ | ❓ | ❌ |
| Apache Hive | ✅ | ❌ | ❌ |
| Elasticsearch | ✅ (ES|QL) | ❌ | ❌ |
| 达梦 DM8 | ✅ | ❌ | ❌ |
| Kingbase | ❌ | ✅ v1.2.0 | ❌ |
| SQL Server | ❌ | ❓ | ✅ |
| CSV/Excel | ✅ (上传) | ✅ | ✅ |
| **总数** | **8** | ~4-5 | ~6-7 |

**评估**: Lingwen 在多数据源覆盖面上领先（8 种），特别是国产数据库（DM8）和大数据组件（Hive、Doris、ES）。SQLBot 支持国产 Kingbase。DB-GPT 覆盖主流关系库。

### 2.3 多数据源实现方式

| 维度 | Lingwen | SQLBot | DB-GPT |
|------|---------|--------|--------|
| **架构模式** | 插件化注册 + 抽象基类 | 驱动配置 | 连接器 + SDK |
| **Async/Sync 降级** | ✅ sync→to_thread 自动降级 | ❓ | 通过 Ray 分布式 |
| **非 SQL 执行** | ✅ ES|QL, HiveQL 原生 | ❌ | ❌ |
| **方言自动注入** | ✅ 动态获取+注入 prompt | ❓ | ✅ prompt 模板 |

**评估**: Lingwen 的插件架构更优雅，sync/async 自动降级是所有项目中独有。DB-GPT 的分布式执行适合大规模部署。

### 2.4 LLM 模型支持

| 能力 | Lingwen | SQLBot | DB-GPT |
|------|---------|--------|--------|
| **模型数量** | 5 种（DS/Kimi/OpenAI/GLM/Minimax） | 多种 | 20+ |
| **动态切换** | ✅ set-default API | ✅ | ✅ |
| **私有化部署** | ❌ | ❓ | ✅ 核心优势 |
| **模型微调** | ❌ | ❌ | ✅ LoRA/QLoRA |
| **多模型编排** | ❌ | ❌ | ✅ SMMF 框架 |

**评估**: DB-GPT 的模型管理（SMMF）最为成熟，支持私有化部署和微调。Lingwen 满足基本需求，但缺乏私有化部署能力。

## 六、Lingwen 优劣势总结

### 优势 🟢

1. **管线最精细**: 8 步完整管线，每步可观测、可追溯
2. **数据源最多**: 8 种数据源含国产数据库和大数据组件
3. **插件架构优雅**: 适配器模式 + sync/async 自动降级
4. **方言注入独特**: 根据数据源类型自动注入 SQL 方言到 LLM prompt
5. **测评模块完善**: 测试集管理、批量执行、实时进度、详情报告闭环
6. **业务场景深度**: 预警→案件工作流贴合政府大数据监督场景
7. **前后端一体化**: React + FastAPI + E2E 验证全链路打通
8. **流式+多轮**: SSE 实时推送 + history 上下文管理

### 劣势 🔴

1. **私有化部署缺失**: 不支持本地 LLM 部署，依赖云端 DeepSeek API
2. **工作流编排固化**: LangGraph 硬编码 DAG，缺乏可视化编排能力
3. **无模型微调**: 无法通过微调提升特定场景准确率
4. **无沙箱执行**: SQL 执行无隔离环境
5. **可嵌入性弱**: 无法作为组件嵌入第三方系统
6. **社区生态空白**: 无开源社区、无插件市场、无外部贡献者

### 差异化定位建议

| 方向 | 借鉴定标 |
|------|---------|
| **短期(1-2月)** | 参照 SQLBot：MCP 协议支持、Docker 快速部署、工作空间隔离 → 提升可集成性和安全性 |
| **中期(3-6月)** | 参照 DB-GPT：AWEL 编排 → 可拖拽 Agent 工作流；微调管线 → 提升领域 SQL 准确率 |
| **长期(6月+)** | 生成式 BI（对话→仪表盘）、沙箱执行、私有化模型部署 |
